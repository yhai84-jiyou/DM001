## 1. 项目概述

### 1.1 项目目标
构建一个**内部使用**的产品帮助手册网站，为团队提供统一的文档编辑、管理和展示平台。

### 1.2 项目背景
- 此前使用开源工具拼接前后端方案，前后端联动不稳定、问题频出
- 需要一个**前后端一体**的整体方案，从零构建
- 展示效果参考 [Easy Vibe](https://datawhalechina.github.io/easy-vibe/)（基于 VitePress 的文档站风格）

### 1.3 用户角色

| 角色 | 人数 | 说明 |
|------|------|------|
| 管理员 (ADMIN) | 1-3 人 | 系统管理，创建用户，管理所有内容 |
| 编辑者 (EDITOR) | ~20 人 | 各自负责不同板块的文档编辑 |
| 前台读者 | 不限 | 内部用户，无需登录即可浏览文档 |

### 1.4 核心原则
- **简单部署**：Docker 一键部署，支持整盘迁移
- **草稿与发布分离**：后台编辑不影响前台展示，手动发布才上线
- **版本可追溯**：每次发布有版本号和更新说明
- **操作可审计**：所有操作记录在日志中
- **易于分发**：完整的文档（需求、使用手册、部署手册）便于交付给其他团队

| 编号 | 需求 | 优先级 | 说明 |

**权限说明**：
- 不做严格的板块权限控制
- 所有 EDITOR 可以编辑所有文章

### 2.4 文章编辑与发布（核心功能）

#### 2.4.1 文章创建与编辑

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| ART-01 | 创建文章 | P0 | 选择所属分类 + 编辑器模式（富文本/Markdown）|
| ART-02 | 富文本编辑器 | P0 | WangEditor 5，所见即所得，支持图片/视频上传 |
| ART-03 | Markdown 编辑器 | P0 | md-editor-v3，左侧编辑右侧预览 |
| ART-04 | 编辑器模式锁定 | P0 | 创建时选定编辑器模式，之后不可切换 |
| ART-05 | 保存草稿 | P0 | 点击保存，草稿内容存储，**前台不受影响** |
| ART-06 | 导入 Markdown | P1 | 支持导入 .md 文件到 Markdown 编辑器 |
| ART-07 | 导入 Word | P1 | 支持导入 .docx 文件到富文本编辑器（mammoth.js 转换） |

#### 2.4.2 草稿与发布分离（关键需求）

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| PUB-01 | 草稿不影响前台 | P0 | 后台编辑/保存的内容是草稿，前台始终展示上一次发布的版本 |
| PUB-02 | 手动发布 | P0 | 只有点击「发布」按钮，内容才同步到前台 |
| PUB-03 | 发布填写版本信息 | P0 | 发布时弹窗，要求填写：版本号（如 v1.0）+ 更新说明 |
| PUB-04 | 单草稿机制 | P0 | 同一篇文章同时只能有一个草稿 |
| PUB-05 | 取消发布 | P1 | 可将已发布文章取消发布（前台不再可见） |

**技术实现**：article 表存两套字段 —— `draft_*`（草稿，后台编辑用）和 `published_*`（已发布，前台展示用）。

#### 2.4.3 版本管理

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| VER-01 | 版本快照 | P0 | 每次发布自动创建不可变的版本快照（标题+内容+HTML） |
| VER-02 | 版本历史列表 | P0 | 显示所有发布版本（版本号、更新说明、发布者、时间） |
| VER-03 | 查看历史版本 | P1 | 只读预览某个历史版本的内容 |
| VER-04 | 回滚到历史版本 | P1 | 将某版本内容加载为新草稿（不直接覆盖前台，需要再次发布） |

#### 2.4.4 文章删除

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| DEL-01 | 软删除 | P0 | 删除文章 = 标记 deleted，前台不可见，进入回收站 |
| DEL-02 | 回收站 | P1 | 显示已删除文章列表 |
| DEL-03 | 恢复文章 | P1 | 仅 ADMIN 可从回收站恢复文章 |
| DEL-04 | 彻底删除 | P1 | 仅 ADMIN 可彻底删除（不可恢复，同时清除版本历史） |

### 2.5 前台可见性控制

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| VIS-01 | 分类级别可见性 | P0 | 每个分类有「前台可见」开关，关闭后该分类及所有子内容前台不可见 |
| VIS-02 | 文章级别可见性 | P0 | 每篇文章有「前台展示」开关，独立于发布状态 |
| VIS-03 | 继承规则 | P0 | 父分类不可见 → 子分类和文章自动隐藏（即使子级自身设为可见） |
| VIS-04 | 可见性管理页 | P1 | 完整目录树 + 开关，一目了然管理可见性 |
| VIS-05 | 批量操作 | P2 | 勾选多个分类/文章，批量设置可见性 |

**可见性与发布的关系**：
- 发布 = 内容定版，创建版本快照（内容层面）
- 可见性 = 是否对前台展示（展示层面）
- 一篇文章可以是"已发布但前台隐藏"的状态

**前台可见的最终条件**（全部满足）：
1. 文章已发布（status=PUBLISHED）
2. 文章 visible=true
3. 所属分类（及所有上级分类）visible=true
4. 文章未被删除（deleted=false）

## 3. 非功能需求

### 3.1 性能

| 编号 | 需求 | 说明 |
|------|------|------|
| PERF-01 | 文章读取缓存 | 使用 Caffeine 本地缓存，发布/编辑时自动清除 |
| PERF-02 | 前台加载速度 | 首屏加载 < 3 秒（内网环境） |

### 3.2 安全

| 编号 | 需求 | 说明 |
|------|------|------|
| SEC-01 | XSS 防护 | 后端 jsoup 白名单清洗 + 前端 DOMPurify 二次净化 |
| SEC-02 | JWT 认证 | Secret 从环境变量读取，合理过期时间 |
| SEC-03 | 登录速率限制 | 防暴力破解 |
| SEC-04 | 文件上传安全 | MIME 白名单、大小限制、UUID 重命名、上传目录独立于 static |
| SEC-05 | 密码加密 | BCrypt 哈希存储 |
| SEC-06 | 错误信息 | 生产环境隐藏堆栈跟踪信息 |

### 3.3 部署与运维

| 编号 | 需求 | 说明 |
|------|------|------|
| OPS-01 | Docker 部署 | docker-compose 一键启动 |
| OPS-02 | 整盘迁移 | 只需复制 data 目录（SQLite + uploads），新服务器 docker-compose up 即可恢复 |
| OPS-03 | 数据备份 | 提供备份脚本，建议设置定时备份 |
| OPS-04 | 数据持久化 | Docker volume 挂载确保数据不随容器删除而丢失 |

### 3.4 可维护性

| 编号 | 需求 | 说明 |
|------|------|------|
| DOC-01 | 需求文档 | 本文档 |
| DOC-02 | 使用手册 | 后台操作指南，面向编辑者和管理员 |
| DOC-03 | 部署手册 | 安装、配置、迁移、备份指南，面向运维人员 |

## 6. 约束与限制

- **内部使用**：不需要 SEO 优化
- **不需要多语言**：UI 和内容均为中文
- **不做严格权限**：所有编辑者可编辑所有文章，通过日志追溯
- **单文件数据库**：SQLite 适合中小规模（<10万篇文章），如需大规模可迁移到 PostgreSQL
- **文件上传限制**：单文件 < 300MB
- **编辑器不可切换**：文章创建时选定编辑器模式，后续不可更改
